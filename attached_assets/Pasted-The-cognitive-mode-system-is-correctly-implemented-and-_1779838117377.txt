The cognitive mode system is correctly implemented and the deterministic boundary remains intact. The next phase should focus on stabilization, unification, and preventing long-term architectural fragmentation as additional reasoning modes evolve.

Do not expand feature count aggressively yet.

The current priority is:
- reducing duplicated logic
- standardizing cognition flow
- preventing prompt sprawl
- improving routing consistency
- preparing for scalable long-term maintenance

Implement a dedicated CognitiveRouter layer.

Right now, mode logic appears partially distributed across SlowBrain and local parsing paths.

Centralize all cognition-selection behavior into a single routing system responsible for:
- selecting reasoning mode
- selecting provider/model
- selecting prompt profile
- selecting memory budget
- selecting history window
- selecting deterministic fallback behavior

SlowBrain should become a consumer of CognitiveRouter decisions rather than containing scattered mode heuristics internally.

Target architecture:
Player Input
    ↓
CognitiveRouter
    ↓
Deterministic Parser OR SlowBrain
    ↓
Structured Intent
    ↓
Planner → Arbitrator → Executors

The router should output a normalized “CognitiveDecision” object:
- selectedMode
- provider
- model
- promptProfile
- tokenBudget
- memoryBudget
- deterministicAllowed
- fallbackStrategy
- reasoningDepth

This prevents mode logic from becoming fragmented across files.

Unify intent schemas.

Currently deterministic parsing and LLM parsing risk diverging over time.

Create a canonical internal intent schema used by:
- deterministic parser
- local lightweight models
- deep reasoning models
- REST endpoints
- planners

All intent sources must normalize into the same structure before entering the Planner.

Do not allow separate intent formats to emerge.

Add confidence scoring to all intent generation paths.

Examples:
- deterministic parser confidence
- lightweight model confidence
- deep reasoning confidence

Low-confidence intents should:
- request clarification
- downgrade scope
- avoid dangerous assumptions

Never allow low-confidence interpretation to silently execute destructive actions.

Implement mode transition hysteresis.

Avoid rapid mode switching every message.

Example bad behavior:
lightweight → deep → lightweight → deep every few seconds

Add:
- cooldown windows
- stability weighting
- recent-context weighting
- active-task awareness

The bot should remain cognitively stable during sustained activities.

Implement compact prompt profiles.

Instead of large monolithic prompts:
- lightweight.prompt
- balanced.prompt
- planning.prompt
- social.prompt
- builder.prompt
- deepreasoning.prompt

Compose prompts modularly based on task requirements.

Do not load:
- building instructions during combat
- deep planning context for simple follow commands
- social memory during mining operations

Prompts should become task-oriented and budget-aware.

Add memory budget enforcement.

Each mode should have strict limits:
lightweight:
- tiny semantic snapshot
- minimal chat history
- no episodic replay

balanced:
- moderate semantic summary
- recent chat
- active task context

deep-reasoning:
- larger world summaries
- planner context
- selected episodic memory
- strategic objectives

Never serialize raw full memory stores into prompts.

Implement intent/result caching.

If identical requests occur repeatedly:
- “follow me”
- “mine wood”
- “come here”
- “build shelter”

reuse normalized intent outputs where valid.

Cache:
- parsed intents
- routing decisions
- compressed memory summaries
- prompt templates

This matters heavily for economy-mode operation.

Add observability for cognition routing.

Telemetry should expose:
- selected mode frequency
- average prompt size
- deterministic bypass frequency
- deep reasoning activations
- routing latency
- confidence distributions
- cache hit rate

This data is essential before future optimization.

Most importantly:
continue enforcing the rule that cognition only produces structured semantic interpretation.

No reasoning mode should:
- execute actions directly
- manipulate Mineflayer APIs
- bypass validation
- bypass planning
- bypass arbitration

The deterministic execution boundary is now a core architectural invariant and should be treated as non-negotiable.
