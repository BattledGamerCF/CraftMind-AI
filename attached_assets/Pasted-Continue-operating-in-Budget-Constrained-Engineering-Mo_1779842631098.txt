Continue operating in Budget-Constrained Engineering Mode.

Mode target: Economy.

Do NOT expand architecture further. The system is now in stabilization and packaging phase.

Primary objective:
turn the system into a predictable, safe, and easy-to-run default experience for new users while preserving all existing functionality.

Focus on usability, defaults, and operational clarity.

1. Default Experience Hardening

Ensure a zero-config startup produces:
- one working bot
- stable behavior immediately
- no provider errors spam
- deterministic fallback if LLM is unavailable

The system should “just work” even with missing API keys.

2. Preset Config Profiles

Add predefined configuration profiles (no UI, just config exports):

- minimal_companion
  (low autonomy, safe behavior, follows player)

- stable_worker
  (task-focused, mining/building, low social noise)

- safe_observer
  (high safety, avoids combat, stays near player/home)

- explorer_light
  (moderate autonomy, controlled exploration)

These should be simple config presets, not new systems.

3. Boot Experience Simplification

On startup, ensure logs clearly show:
- active bot count
- cognitive mode defaults
- provider availability status
- active profile
- persistence status

Remove any redundant or noisy startup logs.

Goal: one glance = system understood.

4. Failure UX Improvement

Improve error messages for end users:

Every major failure should include:
- what happened (simple)
- why it matters (short)
- how to fix it (actionable)

Avoid raw stack traces as primary output.

5. Safe Fallback Behavior Consolidation

If anything fails (LLM, planner, provider, etc):
system must reliably fall back to:
- deterministic intent parsing
- safe idle behavior
- follow player if available

No hard crashes or dead states.

6. Performance Ceiling Guard

Add global safeguards:
- max active tasks per bot
- max perception → planner triggers per second
- max LLM calls per minute (already exists, ensure consistent enforcement)
- cap idle ambient actions per cycle
- prevent task queue explosion

These must default to safe values.

7. Observability Simplification

Ensure /runtime endpoint remains stable but:
- remove redundant fields
- compress memory summaries further
- prioritize “what is the bot doing right now” over full diagnostics

8. Documentation Final Pass (Practical)

Update README with:
- “first run experience”
- preset explanations
- minimal setup path
- troubleshooting quick table (symptom → fix)
- recommended configs per use case

Keep it short and practical.

9. No New Systems Rule

Do NOT introduce:
- new cognitive layers
- new AI subsystems
- new planners or arbitrators
- new memory architectures

Only refinement, consolidation, and usability improvements.

10. Cost Discipline

Strict:
- no broad scans
- no architectural refactors
- no speculative features
- no multi-file rewrites unless necessary for correctness
- no recursive reasoning passes

All changes must be:
- local
- incremental
- reversible
- minimal-risk

System is now entering:
stable public-ready release hardening phase.
