Continue operating in Budget-Constrained Engineering Mode.

Mode target: Economy.

This is the final major usability phase before release.

Primary objective:

Transform Mindcraft from a developer tool into a normal-user application.

A non-technical user should be able to:

1. Download the project
2. Run a single executable or launcher
3. See the dashboard open automatically
4. Create and control bots
5. Never interact with a terminal unless they intentionally choose to

IMPORTANT:

Do NOT build Electron yet.
Do NOT redesign the backend.
Do NOT add gameplay systems.

The goal is a lightweight desktop-launch experience built on top of the existing architecture.

--------------------------------------------------
PHASE 1: ONE-CLICK STARTUP
--------------------------------------------------

Create a Mindcraft Launcher.

Requirements:

- Single command for development
- Single command for production
- Single launcher entry point

Launcher responsibilities:

1. Start API server
2. Start dashboard server
3. Wait until both are healthy
4. Automatically open browser
5. Display friendly startup messages
6. Shut everything down cleanly when launcher exits

The user should not need multiple terminals.

--------------------------------------------------
PHASE 2: DESKTOP FRIENDLY START SCRIPTS
--------------------------------------------------

Create:

Windows:
- Mindcraft.bat
- Mindcraft.ps1

Linux/macOS:
- Mindcraft.command
- start.sh

Requirements:

Double-clicking should work where supported.

The scripts should:

- check dependencies
- show friendly errors
- start services
- open dashboard automatically

Avoid requiring terminal knowledge.

--------------------------------------------------
PHASE 3: SELF-CHECKS
--------------------------------------------------

Before launching:

Verify:

- Node installed
- dependencies installed
- dashboard build exists (if production)
- API port available
- dashboard port available

If something is wrong:

Show a human-readable explanation.

Bad:
"ECONNREFUSED"

Good:
"Mindcraft could not start because port 8080 is already in use."

--------------------------------------------------
PHASE 4: FIRST-RUN EXPERIENCE
--------------------------------------------------

Detect first launch.

If first launch:

Create:

.env

from

.env.example

if missing.

Show a simple welcome screen in the dashboard:

- what Mindcraft is
- how to connect a server
- how to create a bot
- where logs are stored

Only show once.

--------------------------------------------------
PHASE 5: CENTRALIZED CONFIG
--------------------------------------------------

Create a user-friendly config location.

Goals:

Users should not need to edit source files.

Support:

- provider selection
- default model
- dashboard port
- API port
- debug mode

Config should survive upgrades.

--------------------------------------------------
PHASE 6: LOG VIEWER
--------------------------------------------------

Add a simple dashboard page:

Logs

Requirements:

- view recent runtime logs
- auto-refresh
- filter INFO/WARN/ERROR
- search text

No advanced observability system.

Just enough for normal users to understand why something failed.

--------------------------------------------------
PHASE 7: BOT SETUP WIZARD
--------------------------------------------------

Add a guided setup flow.

Wizard should ask:

1. Minecraft server address
2. Username
3. Version (or auto-detect)
4. AI provider
5. Playstyle

Then create the bot.

Goal:

A first-time user should not need to understand any backend concepts.

--------------------------------------------------
PHASE 8: PACKAGING PREPARATION
--------------------------------------------------

Prepare the codebase for future desktop packaging.

DO NOT build Electron yet.

Instead:

Create a clean launcher abstraction that could later be wrapped by:

- Electron
- Tauri
- native installers

without changing backend code.

--------------------------------------------------
PHASE 9: DISTRIBUTION READINESS
--------------------------------------------------

Create:

INSTALL.md

for completely non-technical users.

Assume the reader:

- has never used Node
- has never used a terminal
- has never used GitHub

Provide:

- download steps
- launch steps
- troubleshooting

Use screenshots/placeholders where appropriate.

--------------------------------------------------
PHASE 10: STRICT CONSTRAINTS
--------------------------------------------------

Do NOT:

- add AI systems
- add new gameplay systems
- add autonomous behaviors
- redesign architecture
- migrate to Electron
- introduce cloud dependencies

Focus entirely on:

- usability
- launch experience
- installation experience
- first-run experience
- distribution readiness

Mindcraft is now transitioning from:
"developer project"

to

"software a normal Minecraft player can successfully launch."
