You are not being asked to add new features. You are being asked to diagnose, instrument, and repair an existing Minecraft AI bot that currently connects successfully but fails to perform higher-level tasks reliably.

## Current Observed Behavior

The bot successfully:

- Connects to the Minecraft server.
- Joins the world.
- Occasionally performs actions such as crouching and jumping.

The bot fails to:

- Reliably respond to player chat.
- Reliably execute follow commands.
- Build structures when instructed.
- Execute dashboard-issued build commands without disconnecting.

Additional observations:

- The bot sometimes claims it is following a player but never moves.
- The bot sometimes enters a loop where it repeatedly crouches.
- A structure-generation command issued from the dashboard causes the bot to disconnect.
- Existing logs only show API polling traffic and provide almost no visibility into runtime behavior.

Example log output currently consists primarily of:

GET /api/bots
GET /api/bots/{id}/runtime
304 Not Modified

This provides no useful debugging information.

---

# Objective

Perform a full debugging and observability pass across the project.

Your goal is to identify why the bot is failing and produce detailed logs that make future failures obvious.

---

# Phase 1: Runtime Instrumentation

Add structured logging throughout the entire runtime.

Every major system should emit logs.

## Bot Lifecycle

Log:

- startup
- initialization
- login
- spawn
- respawn
- death
- disconnect
- kicked
- reconnect attempts
- shutdown

Example:

[SPAWN] Bot spawned successfully
[LOGIN] Connected as BotName
[DISCONNECT] Lost connection

---

## Chat System

Log every incoming message.

Example:

[CHAT] Elijah: hello
[CHAT] Elijah: build a shelter

Log every stage of processing.

Example:

[AI] Received user message
[AI] Generating response
[AI] Parsed intent: FOLLOW_PLAYER

Log all outgoing messages.

Example:

[CHAT OUT] Following Elijah

---

## AI Pipeline

For every request:

Log:

- raw user input
- parsed intent
- generated plan
- selected action
- execution result
- errors

Example:

[AI] Intent=FOLLOW_PLAYER
[PLAN] Locate target player
[ACTION] Pathfinder goal assigned

---

## Pathfinder

Add logging for:

- goal assignment
- path generation
- path updates
- path failures
- goal completion

Example:

[PATH] Goal assigned
[PATH] Computing route
[PATH] Route failed
[PATH] Goal reached

If pathfinding fails, print the reason.

---

## Building System

Log:

- structure request
- plan creation
- block collection
- block placement
- completion
- failure

Example:

[BUILD] Shelter requested
[BUILD] Plan generated
[BUILD] Placing block 1/42
[BUILD] Build completed

---

# Phase 2: Crash Detection

Install global error handlers.

Capture:

- uncaught exceptions
- unhandled promise rejections
- async task failures
- worker crashes

Print full stack traces.

Example:

[FATAL] Uncaught Exception
(stack trace)

[ERROR] Unhandled Promise Rejection
(stack trace)

No runtime error should ever disappear silently.

---

# Phase 3: Investigate Known Failures

## Chat Failure

Determine whether:

- chat events are firing
- AI receives chat
- AI generates commands
- command execution occurs

Identify exactly where the pipeline stops.

---

## Follow Failure

The bot sometimes claims:

"Following Elijah"

but never moves.

Determine:

- whether the player was found
- whether a goal was created
- whether pathfinder accepted the goal
- whether path generation succeeded
- whether movement commands were issued

Fix the root cause.

---

## Crouch Loop

The bot repeatedly crouches and occasionally jumps.

Find every location that modifies:

- sneak
- jump
- forward
- back
- left
- right

Identify what loop or behavior is repeatedly issuing control commands.

Ensure control states are cleaned up properly when tasks terminate.

---

## Build Failure

The command:

"build a shelter"

does nothing.

Trace:

chat input
→ intent recognition
→ planning
→ builder execution

Determine where execution stops and repair it.

---

## Dashboard Structure Crash

This is currently the highest-priority bug.

A structure-generation command issued from the dashboard causes the bot to disconnect.

Investigate:

- runtime exceptions
- invalid build plans
- pathfinding failures
- missing resources
- unhandled async errors

Produce the exact root cause.

Do not guess.

Use instrumentation and logs to determine the actual failure.
