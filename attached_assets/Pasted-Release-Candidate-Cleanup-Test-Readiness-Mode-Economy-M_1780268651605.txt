Release Candidate Cleanup & Test Readiness

Mode: Economy.

Mindcraft is feature complete.

No new features.
No architecture changes.
No gameplay changes.
No AI system changes.

Primary objective:

Prepare the repository for real-world Minecraft testing.

--------------------------------------------------
PHASE 1: DEAD CODE AUDIT
--------------------------------------------------

Search for:

- unused files
- unused exports
- unused routes
- unused utility functions
- abandoned scaffolding
- commented-out legacy code
- duplicate implementations

Remove only high-confidence dead code.

Do not remove anything that may still be used indirectly.

--------------------------------------------------
PHASE 2: REPOSITORY CLEANUP
--------------------------------------------------

Verify repository contents.

Remove:

- temporary files
- generated artifacts
- stale documentation
- leftover migration files
- obsolete scripts
- abandoned experiments

Keep:

- source
- docs
- launcher
- dashboard
- configuration
- build tooling

Repository should be clean and understandable to a new contributor.

--------------------------------------------------
PHASE 3: DOCUMENTATION CONSISTENCY
--------------------------------------------------

Cross-check:

- README.md
- INSTALL.md
- RELEASE_CHECKLIST.md
- SECURITY_AUDIT.md
- .env.example

Verify all commands, filenames, ports, URLs, and startup instructions match reality.

Fix any inconsistencies.

--------------------------------------------------
PHASE 4: BUILD VERIFICATION
--------------------------------------------------

Verify:

Development:
- launcher
- API
- dashboard

Production:
- API build
- dashboard build
- static serving
- browser launch flow

Fix only actual issues discovered.

--------------------------------------------------
PHASE 5: TEST READINESS
--------------------------------------------------

Create TESTING.md.

Include:

1. First launch test
2. Bot creation test
3. Minecraft connection test
4. Follow command test
5. Mine command test
6. Build command test
7. Home system test
8. Persistence test
9. LLM fallback test
10. Failure recovery test

Each test should contain:

- setup
- expected result
- pass criteria

Written for a normal user.

--------------------------------------------------
PHASE 6: RELEASE READINESS REPORT
--------------------------------------------------

Produce:

PASS
WARN
FAIL

For each item:

- issue
- file
- action taken

Also include:

Repository Status:
- Ready for Testing
- Needs Work

Do not add features.

Do not redesign systems.

Do not create new architecture.

The objective is a stable, understandable repository that is ready to be launched against a real Minecraft server and evaluated through gameplay rather than further development.
