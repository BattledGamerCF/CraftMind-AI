You are redesigning and rebuilding a Minecraft AI companion system inspired by Mineflayer/Mindcraft-style agent frameworks. The goal is NOT to create a hyper-optimized cheating client, an omniscient PvP bot, or a slow “AI philosopher” that spends 20 seconds thinking before placing a plank. The goal is to create a believable, performant, autonomous Minecraft companion that behaves similarly to a real player while remaining efficient enough to run locally on consumer hardware.

The project should prioritize:
- responsiveness
- stability
- modularity
- scalability
- immersion
- accessibility for non-programmers
- support for the newest Minecraft Java versions
- compatibility with multiplayer environments
- future CurseForge/Fabric/NeoForge mod compatibility
- low inference latency
- minimal hallucination issues
- native gameplay systems instead of excessive AI command parsing

The system should feel like:
“a slightly awkward but competent AI multiplayer companion.”

It should NOT feel like:
- an aimbot
- a hacked client
- a command-line chatbot
- a server automation engine
- a machine that pauses for 15 seconds every time it sees a tree

==================================================
PRIMARY OBJECTIVES
==================================================

The rebuilt system must:

1. Support the latest Minecraft Java version possible.
2. Use a hybrid architecture:
   - high-level AI planning
   - low-level deterministic gameplay systems
3. Remove excessive “internal monologue” or recursive reflection systems that dramatically slow response times.
4. Reduce token usage and inference overhead wherever possible.
5. Make the bot feel naturally human-like rather than mathematically optimal.
6. Support lightweight autonomous building.
7. Support lightweight defensive PvP.
8. Support multiplayer interaction and following behavior.
9. Be modular enough for future expansion.
10. Run well on local consumer hardware, including Apple Silicon Macs.

==================================================
CORE ARCHITECTURE
==================================================

The system should use TWO DISTINCT BRAINS:

--------------------------------------------------
1. HIGH-LEVEL AI BRAIN (SLOW BRAIN)
--------------------------------------------------

This layer uses an LLM.

Responsibilities:
- conversation
- planning
- interpreting vague goals
- social interaction
- deciding what task to perform
- interpreting player intent
- choosing structure styles
- reacting emotionally/socially
- memory summarization
- contextual reasoning

This layer should:
- run infrequently
- avoid recursive loops
- avoid self-reflection spam
- avoid endless chain-of-thought
- avoid repeated prompt rebuilding

The LLM should NOT:
- individually place blocks
- directly control combat clicks
- constantly micromanage movement
- generate hundreds of commands
- narrate every action

The AI layer should issue:
HIGH-LEVEL INTENT ONLY.

Examples:
- “build a small oak cabin”
- “follow player”
- “gather food”
- “retreat from danger”
- “defend self”
- “explore nearby terrain”

==================================================
2. LOW-LEVEL FAST BRAIN
==================================================

This layer must be deterministic code, NOT LLM inference.

Responsibilities:
- movement
- pathfinding
- mining
- building execution
- combat reactions
- inventory management
- obstacle avoidance
- block placement
- hunger management
- environmental reactions
- navigation
- short-term reactive behavior

This layer should:
- run continuously
- be highly optimized
- avoid unnecessary AI calls
- behave predictably
- support asynchronous execution
- use finite state machines or behavior trees

The FAST BRAIN should be capable of:
- executing goals autonomously
- handling failures gracefully
- recovering from pathfinding issues
- performing tasks without constant AI guidance

==================================================
REMOVE OR REDUCE THESE SYSTEMS
==================================================

The existing framework likely contains:
- self-prompting loops
- recursive reflection
- excessive memory summarization
- “thinking” prompts
- verbose command chatter
- repeated contextual rebuilding
- command parsing bottlenecks

These should be:
- removed
- minimized
- cached
- event-driven instead of loop-driven

The system should NEVER:
- freeze for long periods while “thinking”
- generate philosophical responses instead of actions
- explain every action aloud
- constantly speak in chat unnecessarily

==================================================
PERFORMANCE OPTIMIZATION REQUIREMENTS
==================================================

The rebuilt system should prioritize:
- low latency
- asynchronous processing
- low token usage
- prompt caching
- memory trimming
- modular systems
- low CPU overhead
- low RAM overhead
- Apple Silicon optimization

Optimization targets:
- responsive on M2/M-series Macs
- usable with 5B-7B local models
- minimal blocking operations
- reduced inference frequency
- reduced synchronous waits

The system should:
- reuse prompt templates
- cache embeddings where appropriate
- avoid unnecessary summarization
- avoid repeated world-state serialization

The system should support:

Examples:

==================================================
HUMANIZATION SYSTEM
==================================================

The bot should behave BELIEVABLY HUMAN, not perfectly optimized.

Add:
- small camera drift
- imperfect mining aim
- occasional hesitation
- random idle behavior
- contextual chat
- delayed reactions
- movement variation
- imperfect combat timing

The bot should:
- look around naturally
- stop occasionally
- reposition awkwardly sometimes
- avoid robotic precision

The system should NOT:
- intentionally evade anti-cheat
- simulate human deception maliciously
- impersonate real players
- behave like an aimbot

The goal is:
BELIEVABILITY, NOT DECEPTION.

==================================================
PVP / COMBAT SYSTEM
==================================================

The bot should support LIGHT defensive PvP only.

Requirements:
- defend self when attacked
- retreat when overwhelmed
- avoid overreacting
- avoid attacking friendly players
- avoid instantly retaliating to accidental hits
- support basic melee combat
- support shield usage if practical
- support fleeing behavior

The combat system should:
- use human-like reaction timing
- occasionally miss
- avoid impossible tracking
- avoid perfect aim
- avoid snap rotations
- avoid wall tracking
- avoid crystal-PvP-style mechanics

The combat system should feel:
- cautious
- imperfect
- reactive
- believable

NOT:
- hyper-competitive
- machine-perfect
- exploitative
